# B站黄金UP主历史信号研究工具设计

## 1. 目标

构建一个仅在本机运行的研究工具。用户添加一个或多个B站UP主主页，系统获取其最近六个月公开投稿，临时下载音轨，使用本地语音模型转写，再调用MiniMax把每期视频中对黄金的观点抽取为结构化信号。系统将信号与XAU/USD后续行情对齐，生成按UP主独立统计的历史合订本和能力排行榜。

首版回答两个问题：

1. 某个UP过去半年具体说过什么、何时说、后来走势如何。
2. 在统一且无未来数据的计算规则下，不同UP的历史方向判断表现如何。

工具不提供当前买卖建议，不自动交易，不承诺收益，也不把历史表现解释为未来能力保证。

## 2. 首版边界

### 包含

- 仅支持B站公开视频和UP主空间公开投稿列表。
- 每个UP主是一条独立研究线。
- 默认回看窗口为运行日向前183天。
- 本地Whisper中文转写。
- MiniMax文本结构化抽取，并发上限固定为3。
- XAU/USD日线行情对齐。
- 1、5、20个交易日固定评价窗口。
- 排行榜、UP主合订本、视频详情和人工复核。
- SQLite持久化、断点续跑和失败重试。

### 不包含

- 评论、弹幕、粉丝画像、真实身份或联系方式采集。
- 会员、付费、登录受限、已删除或非公开内容。
- 实时喊单、推送、自动交易、仓位建议或收益保证。
- 公网部署、多用户、账号系统和云端数据库。
- B站之外的平台。
- 黄金以外的资产。
- 分钟级行情和精确盘中成交回放。

## 3. 技术方案

采用单体Python应用，减少部署组件：

- Web与本地API：Flask。
- 数据库：Python内置SQLite。
- B站公开投稿发现和音轨获取：`yt-dlp`。
- 音频转写：`faster-whisper`多语言`small`模型。
- 文本抽取：MiniMax中国区OpenAI兼容接口。
- 网络客户端：`httpx`。
- 行情：Stooq公开XAU/USD日线CSV；行情源实现为接口，便于以后替换。
- 图表：随应用静态提供Chart.js，不依赖运行时CDN。
- 测试：pytest。

应用默认监听`127.0.0.1:8765`，没有显式配置时拒绝监听公网地址。

## 4. 模块边界

### `goldbook/config.py`

读取环境变量并验证配置。MiniMax密钥只从`.env`或进程环境读取，永不返回给浏览器、写入数据库或日志。

默认配置：

- `LOOKBACK_DAYS=183`
- `MINIMAX_BASE_URL=https://api.minimaxi.com/v1`
- `MINIMAX_MODEL=MiniMax-M3`
- `MINIMAX_MAX_CONCURRENCY=3`，代码层不允许配置为大于3。
- `WHISPER_MODEL=small`
- `WHISPER_DEVICE=auto`
- `WEB_HOST=127.0.0.1`
- `WEB_PORT=8765`

### `goldbook/db.py`

负责SQLite建表、事务和仓储接口。业务模块不直接拼接SQL。

核心实体：

- `creators`：B站UID、昵称、空间URL、启用状态、同步时间。
- `videos`：BV号、UP、标题、发布时间、时长、原链接、处理状态、错误摘要。
- `transcripts`：分段时间、文本、模型、文本哈希、创建时间。
- `analyses`：MiniMax原始响应哈希、结构化信号、置信度、人工复核状态和修订记录。
- `prices`：交易日及XAU/USD OHLC。
- `outcomes`：信号的入场价、1/5/20日退出价、方向收益和成熟状态。
- `jobs`：同步任务进度、阶段、重试次数和错误。

BV号唯一，重复同步不重新下载。转写文本哈希未改变时不重复调用MiniMax。

### `goldbook/bilibili.py`

调用`yt-dlp`发现空间投稿和读取单视频元数据。只接受标准B站空间URL、UID或BV链接。

安全与资源规则：

- 只处理公开可访问内容。
- 对空间列表按发布时间过滤183天，不做全量历史回溯。
- 音轨放入每任务独立临时目录。
- 单视频完成转写或失败后都删除音轨。
- 默认串行下载，加入随机小间隔和指数退避。
- 不提供Cookie、登录绕过、代理池或反风控功能。
- 保存原视频URL和元数据，不保存封面、头像或视频文件。

### `goldbook/transcribe.py`

延迟加载单例Whisper模型，默认自动选择设备：

- CUDA可用时使用CUDA与`float16`。
- 否则CPU与`int8`。

转写固定语言为中文，开启VAD，输出带起止时间的分段文本。模型首次运行时下载到用户缓存。转写失败可以重试，不会触发MiniMax调用。

### `goldbook/minimax.py`

将去标识后的字幕正文提交给MiniMax。请求不包含UP昵称、UID、主页地址或密钥之外的本机信息。

全局异步信号量固定为3；每个视频最多重试3次，对429和5xx执行指数退避。请求结果以字幕哈希缓存。

MiniMax必须返回以下结构；无法解析或字段冲突时标记为`needs_review`，不得进入排行榜：

```json
{
  "direction": "bullish | bearish | neutral | no_signal",
  "strength": 1,
  "confidence": 0.0,
  "horizon_text": null,
  "target_price": null,
  "stop_price": null,
  "conditions": [],
  "is_retrospective": false,
  "is_news_only": false,
  "evidence": [
    {"start_sec": 0.0, "end_sec": 0.0, "quote": ""}
  ],
  "summary": ""
}
```

证据引文必须能在对应字幕时间段中找到；否则删除证据并要求人工复核。`neutral`和`no_signal`不进入收益评价。

### `goldbook/market.py`

提供统一行情接口并实现Stooq XAU/USD日线适配器。每次同步增量更新近一年OHLC并存入SQLite。返回值按交易日排序并拒绝重复日期或无效价格。

如果行情源不可用，视频处理仍可完成，但结果保持`unpriced`，后续行情刷新后补算。

### `goldbook/scoring.py`

首版采用可解释且无未来数据的固定规则：

- 入场：视频发布后的下一个可用交易日开盘价。
- 退出：从入场交易日起第1、5、20个交易日收盘价。
- 黄金原始收益：`exit_close / entry_open - 1`。
- 信号收益：看多等于原始收益；看空等于原始收益的相反数。
- 命中：信号收益大于0。
- 中性、无信号、纯新闻、纯历史回顾、未复核和未到期记录不计入统计。

排行榜以5日窗口为主，展示：

- 成熟信号数量。
- 看多/看空数量。
- 1/5/20日命中率。
- 1/5/20日平均每条信号收益。
- 5日逐条复合收益：按信号发布日期排序，对每条归一化信号收益执行`product(1+r)-1`。
- 最佳、最差单条结果。
- MiniMax低置信度和人工修订占比。

少于3条已复核且成熟的5日信号标记为`样本不足`，不进入正式名次。界面避免使用“专家”“骗子”“反向指标”等人格化结论。

逐条复合收益是研究统计，不是可执行组合：信号可能时间重叠，首版不模拟资金占用、手续费或滑点，页面必须明确说明。

### `goldbook/jobs.py`

使用应用内后台线程执行任务，不引入Redis或独立队列。

单个UP同步流程：

1. 发现半年内公开视频。
2. 为新视频建立任务记录。
3. 逐视频下载音轨。
4. 本地转写并删除音轨。
5. 最多3路并发调用MiniMax。
6. 更新行情并计算成熟结果。
7. 刷新排行榜缓存。

任务可暂停和重试。应用重启时把中断的`running`任务恢复为`pending`。同一视频只允许一个活跃任务。

## 5. Web界面

### 首页与UP管理

- 添加UP空间URL、UID或单个BV链接。
- 展示最近一次同步、半年视频数、已处理数、失败数和当前阶段。
- 提供开始同步、重试失败、停用UP、删除UP本地数据。

删除UP采用二次确认，删除数据库记录、转写和分析结果；不会影响其他UP共享的行情缓存。

### 排行榜

- 正式排名和样本不足区分展示。
- 默认按5日平均信号收益排序，可切换命中率、复合收益和样本数。
- 每个指标带口径提示，不展示单一不透明总分。
- 未复核、未成熟和无信号数量单独展示，防止选择性呈现。

### UP主合订本

- 最近半年视频按时间倒序。
- 每张卡显示标题、发布时间、方向、强度、短证据、入场价和1/5/20日结果。
- 可过滤看多、看空、中性、无信号、待复核和处理失败。
- 点击原视频链接回到B站，不嵌入或重新播放视频。

### 视频详情与人工复核

- 分段字幕仅在本机详情页展示。
- MiniMax抽取字段可修改；保存时记录修改前后JSON和时间。
- 方向或证据被人工修改后重新计算结果。
- 图表展示发布日、入场日和1/5/20日退出点。
- 提供“排除出排行榜”开关和原因字段。

## 6. 隐私、著作权和产品措辞

- 应用仅本机访问，不提供公网部署脚本。
- 音视频只在临时目录存在，转写后删除。
- 不公开完整转写，不复制封面或头像。
- 页面展示必要短引文、时间戳和原视频链接。
- 数据页面提供删除和更正入口。
- 所有排行均称“历史信号统计”，不声称UP的真实职业能力或人格品质。
- 页面固定展示：自动转写和模型抽取可能有误；历史结果不代表未来；不构成投资建议。
- MiniMax密钥已通过聊天提供，实施时仅写入本地`.env`；交付说明要求用户轮换密钥。

## 7. 错误处理

- B站访问失败：记录HTTP/提取器摘要，不保存页面内容，允许稍后重试。
- 视频无音轨或过长：记录失败原因，不阻塞UP其他视频。
- Whisper模型下载失败：任务保持待重试，Web提示所需磁盘空间与网络状态。
- MiniMax限流：遵守3并发并指数退避；超过重试次数进入待重试。
- MiniMax非JSON：尝试提取首个JSON对象；仍失败则进入人工复核，不猜测字段。
- 行情缺失：结果保持未定价，不计排行榜。
- 数据库写入：每个视频阶段使用短事务，避免长任务持锁。
- 应用崩溃：已完成阶段不重做，临时目录在下次启动时清理。

日志默认不包含密钥、完整字幕或MiniMax完整响应，只记录视频BV号、阶段、耗时和错误类型。

## 8. 测试与验收

单元测试覆盖：

- URL和UID解析。
- 半年时间过滤与幂等入库。
- MiniMax JSON校验、证据匹配、并发不超过3。
- XAU/USD交易日查找和1/5/20日收益计算。
- 看多/看空符号处理、未成熟排除、最少样本规则。
- 删除UP时不删除共享行情。
- 配置拒绝公网监听和超过3的MiniMax并发。

集成测试使用本地伪音频、固定字幕、固定MiniMax响应和固定行情CSV，不依赖B站、模型下载或外部API。

手动验收：

1. 添加一个测试UP或单个BV链接。
2. 确认音轨下载后被删除。
3. 确认字幕带时间戳且MiniMax抽取包含可定位证据。
4. 人工修改方向并确认结果重新计算。
5. 确认未满5个交易日的视频不进入5日排名。
6. 确认浏览器源代码和网络响应中没有MiniMax密钥。
7. 重启应用，确认任务和历史数据保留且不会重复处理。

## 9. 本地运行与交付

交付内容：

- Python源码、测试和数据库迁移。
- `requirements.txt`和锁定的直接依赖版本。
- `.env.example`，不包含真实密钥。
- PowerShell一键安装与启动脚本。
- README：安装、模型大小、首个UP导入、备份、删除和密钥轮换。
- 一个完全离线的演示数据集，用于不开启B站或MiniMax也能查看Web页面。

目标命令：

```powershell
.\scripts\setup.ps1
.\scripts\start.ps1
```

首次运行下载Whisper模型，之后模型从本机缓存加载。业务数据默认存放在仓库内`data/goldbook.db`，音轨临时目录位于`data/tmp/`并在成功或失败后清理。`data/`、`.env`和模型缓存不得提交到Git。

## 10. 外部依赖与已知限制

- B站页面和`yt-dlp`提取器可能变化，抓取能力无法永久保证。
- Stooq免费行情可能延迟、缺失或调整历史值，因此数据库保留抓取时间。
- 日线无法精确还原视频发布后的盘中可交易价格；统一使用下一交易日开盘是保守且可复现的近似。
- Whisper对口音、行业术语和背景音乐可能误识别，因此证据必须人工复核。
- MiniMax结构化抽取是辅助，不是事实裁判；低置信度结果不得计榜。
- 半年样本可能很少，排行榜必须展示样本数量，不能把短期结果外推为长期能力。
