# B站黄金观点逐条提取与严格时间对齐设计

## 1. 目的与范围

本设计扩展现有 Goldbook 本地研究工具：不再把一条视频压缩成一个总方向，也不再用固定的 1、5、20 个交易日统一评价。系统使用 MiniMax-M3 从每条视频字幕中抽取多个可验证观点，识别点位、条件、方向和各自的时间范围，再用视频发布之后的 XAU/USD OHLC 行情逐条验证。

结果按“视频 → 观点 → 实际结果”展示，并按 UP 主汇总能力。系统保持本地私有、仅处理公开 B 站内容、不保留音视频、不构成投资建议。

本设计覆盖原设计中的以下旧规则：

- 固定 1、5、20 个交易日评价窗口；
- 每个视频只有一个 `SignalAnalysis` 方向和一个 `Outcome`；
- 自动结果必须经过 `approved` 人工复核才能进入排行榜。

旧表和旧页面在迁移期保留兼容读取，但新排行榜和新详情以逐条观点结果为准。

## 2. 已确认的原则

1. 一个视频可以有零个、一个或多个观点。
2. M3 必须区分每个观点的品种、方向、点位、条件、周期和字幕证据。
3. 时间严格以视频公开发布时间为起点，绝不使用发布前或包含发布前成交的行情验证预测。
4. 不设置“未说明则 20 天”的默认周期。
5. “短期、中期、长期”等相对表达必须结合字幕上下文转换成具体交易日数或交易日区间，同时保存原话、推断来源和置信度。
6. 完全没有时间表达且无法从上下文推断的方向观点，有效期截止到该 UP 下一条同品种、含可执行预测的视频发布时间；若尚无下一条，则保持未成熟。
7. 有明确周期的观点按自身周期持续有效。后续视频只有在明确修订、取消或替代同一观点时才提前终止它，不能因为 UP 日更而自动截断中长期观点。
8. 结构和证据校验通过后自动评价，不要求人工审批。人工入口只用于可选纠错，并保留修订记录。
9. LLM 负责理解语言和生成结构；命中、距离、时间顺序和收益计算必须由确定性程序完成。
10. 既有 99 条本地字幕直接重新调用 M3，不重新下载视频，也不重新转写。

## 3. 方案选择

### 3.1 采用：逐条观点事件模型

每个视频分析产生一组 `ForecastClaim`，每个观点有独立周期和评价结果。该方案最符合日更视频、多点位、多周期并存的事实，也能解释“方向对但点位没到”或“点位到达但超时”等情况。

### 3.2 未采用：增强单一视频信号

继续在 `SignalAnalysis` 上增加多个目标和周期，改动较小，但无法可靠表达同一视频中互相独立甚至相反的短、中、长期观点，也难以逐条审计。

### 3.3 未采用：让 LLM 直接判断预测是否正确

让 M3 同时阅读未来行情并给结论实现最快，但难以复现，容易把未来信息带入抽取过程，也不能保证点位和时间计算一致。因此 M3 只看发布时已存在的信息；程序单独读取未来行情评价。

## 4. 观点结构

### 4.1 `ForecastClaim`

每条观点至少保存：

- `claim_id`：由分析修订号和观点序号形成的唯一标识；
- `bvid`、`analysis_revision`、`claim_index`；
- `instrument`：如 `XAU_USD_SPOT`、`COMEX_GC`、`SHFE_AU`、`UNKNOWN`；
- `claim_type`：`directional_move`、`target_touch`、`cross_above`、`cross_below`、`hold_above`、`hold_below`、`range`、`volatility` 或 `sequence`；
- `direction`：`bullish`、`bearish`、`neutral` 或空；
- `operator`：`>=`、`<=`、`between`、`sequence` 等机器可执行条件；
- `level_low`、`level_high`、`stop_price`：可为空；
- `condition_text`：预测成立条件的原始语义；
- `horizon_text`：视频原话，如“短期”“下周”“年底”；
- `horizon_source`：`explicit_exact`、`explicit_relative`、`context_inferred` 或 `unknown`；
- `horizon_min_trading_days`、`horizon_max_trading_days`、`horizon_point_trading_days`；
- `deadline_at`：能由明确日期计算时保存带时区截止时间；
- `time_confidence` 和整体 `confidence`；
- 一至多条带 `start_sec`、`end_sec`、短引文的字幕证据；
- `supersedes_claim_id`：后续视频明确修改旧观点时使用；
- `extraction_status`：`auto_validated`、`unresolved`、`excluded` 或 `human_corrected`。

同一句话可以产生复合观点。例如“回踩 4650 后看 4700”应产生带顺序约束的两个事件，而不是只留下“看涨”。“锁定 4700”不能仅凭关键词决定含义：M3 必须结合原句判断它是目标触达、突破、站稳还是支撑；程序再根据对应算子验证。

### 4.2 时间推断输出

M3 对每个相对周期给出一个具体点估计和一个允许的不确定区间。例如“短期”可以输出 2 个交易日、区间 1–3 个交易日，但不能只返回“短期”。页面同时展示原话和换算结果，不能把推断伪装成作者明确说出的日期。

推断只允许使用：

- 当前视频字幕及标题；
- 当前视频发布时间和当时已知的日历；
- 同一句或相邻上下文中出现的“今天、这周、月底、非农前后”等表达。

禁止把未来视频发布时间、未来行情或事后结果提供给抽取模型。若上下文不足，`horizon_source=unknown`，不得臆造天数。

## 5. 严格时间对齐

### 5.1 时间基准

- B站发布时间保存为带时区的绝对时间，并以 `Asia/Shanghai` 显示。
- 行情提供者的交易日边界必须记录并统一转换；所有比较以绝对时间或明确的交易日序号完成。
- 当前只有日线 OHLC。视频发布当日的日线包含发布前成交，因此整根发布日 K 线不能用于验证发布后的预测。
- 第一个可用观察点是发布时间之后第一根完整交易日 K 线。周末或休市发布的视频从下一完整交易日开始。
- “今天、今晚、日内几小时”等观点需要发布后分时行情。日线数据无法无泄漏验证时，标记 `unresolved_intraday_data`，既不算命中也不算失败。

### 5.2 周期换算

- 明确日期以该日期对应交易时段结束为截止；休市日顺延到下一个交易日，并在结果中说明。
- “明天、下个交易日”是第一个完整交易日。
- “本周、下周、月底、季度末、年底”根据发布日期计算具体日期，再映射到交易日。
- “短期、中期、长期”由 M3 给出交易日点估计和区间，最终成熟时间采用区间上界，区间内首次命中仍记录真实命中日期。
- 完全无周期观点在下一条同 UP、同品种、包含可执行预测的视频发布前有效。该机械截止不用于反向推断原观点周期。
- 明确周期观点不会被普通日更视频截断；只有新观点显式修订或取消它时，才以新视频发布时间作为提前截止点。

### 5.3 防止未来数据泄漏

抽取和评价分为两个独立步骤。抽取阶段只接收字幕、标题和发布时间。评价阶段只能读取 `published_at` 之后且不晚于观点截止时间的行情。测试必须覆盖发布当日排除、周末、休市、时区转换、尚未成熟以及后续修订等边界。

## 6. 确定性评价

每条观点产生一个 `ClaimEvaluation`，保存观察窗口、入场参考价、窗口最低/最高/最终收盘、最接近点位和日期、距离百分比、首次命中时间、成熟状态、判定和机器说明。

### 6.1 点位和条件

- `target_touch` / `cross_above`：窗口内 `high >= level` 为命中。
- `cross_below`：窗口内 `low <= level` 为命中。
- `hold_above` / `hold_below`：“站稳”按连续两个完整交易日收盘位于点位同一侧判定。
- `range`：每根 K 线的高低必须按观点所述区间和容许条件判断。
- `sequence`：按首次事件时间验证先后次序，如先回踩 4650，再触达 4700。
- `directional_move`：以首个完整交易日开盘为参考，比较观点截止时收盘及期间最大有利/不利波动。
- `volatility`：只有存在可执行数值范围或幅度时计分；纯“震荡、波动”保留为路径描述，不强行判胜负。

若目标未精确触达，但最接近价格与目标差距不超过 0.5%，显示 `partial_near`；0.5% 只用于“附近/差一点”的次级说明，不能把明确的突破或跌破伪装成精确命中。页面必须同时显示最低价、最高价、最近距离和真实日期。

### 6.2 判定状态

- `hit`：条件在截止时间前完整满足；
- `partial_near`：未满足精确条件，但距离在 0.5% 内；
- `miss`：观察窗口已结束且条件未满足；
- `unresolved`：窗口未成熟、周期未知、缺少所需粒度行情或品种不匹配；
- `superseded`：观点被后续明确修订，保留截断前结果但不当作完整周期失败；
- `excluded`：回顾、纯新闻、玩笑、广告或没有预测含义。

当前行情只支持 XAU/USD 现货。COMEX 黄金、沪金等不得用现货价格代替验证，标为 `unresolved_instrument`。`UNKNOWN` 只有在字幕证据和视频上下文能可靠归一为 XAU/USD 后才能评价。

## 7. 自动化与人工纠错

自动流程为：字幕缓存 → M3 多观点抽取 → JSON/schema 校验 → 字幕证据定位 → 自动入库 → 行情评价。证据可定位、结构合法的观点直接进入统计，不再进入强制 review 队列。

以下情况不会伪装成人工待审：

- API、网络或解析失败：任务失败并按现有策略重试；
- 模型明确无法判断：保存为 `unresolved` 并说明原因；
- 无可执行预测：保存视频级 `no_claim`；
- 不支持的品种或数据粒度：保存为对应 `unresolved_*`。

人工页面保留为“纠错”，允许修改观点类型、品种、点位、周期、条件和证据。每次修改创建新分析修订并重新计算评价；自动原始结果永久保留用于审计，但排行榜只读取最新有效修订。

## 8. 数据持久化与迁移

新增两张核心表：

- `forecast_claims`：保存逐条结构化观点、周期推断、证据、状态和修订关系；
- `claim_evaluations`：保存按行情版本计算的确定性结果和完整可解释中间值。

现有 `analyses` 继续保存视频级摘要和模型原始结构哈希；`outcomes` 作为旧版固定窗口缓存保留到新页面和排行榜迁移完成。新记录不得再依赖 `ReviewStatus.APPROVED` 才能统计。

迁移必须幂等：对已有字幕按 BVID 和字幕哈希重新调用 M3，最大并发仍为 3；相同字幕、模型、提示词版本和分析修订不得重复计费。模型名、提示词版本、字幕哈希和抽取时间都要保存。

行情刷新后仅重新计算 `claim_evaluations`，不重复调用 M3。后续新视频可能为无周期旧观点提供机械截止，或显式修订旧观点，因此创建新分析后要重新评估同 UP、同品种的相关未成熟观点。

## 9. 页面与排行榜

### 9.1 UP 主页面

每个 UP 主仍是一条独立研究线。视频列表逐条显示：

- 发布时间和原视频链接；
- M3 提取的观点数量；
- 已命中、接近、失败、未成熟和不可评价数量；
- 视频级准确率与数据覆盖率；
- 进入“预测与实际逐条对照”详情页的链接。

### 9.2 视频详情页

每个观点单独一张对照卡：左侧显示原预测、点位、条件、原始周期、换算交易日、字幕时间戳和短证据；右侧显示观察窗口、实际高低收、最近距离、首次命中日期和结论。图表标出发布时间、可用行情起点、目标线、截止点、命中点和后续修订点。

### 9.3 UP 能力统计

排行榜不再以 review 状态为门槛。只统计已成熟且可执行的最新观点修订，并同时公开：

- 精确命中率、含 `partial_near` 的接近率；
- 方向正确率、目标点位命中率、条件/顺序命中率；
- 到目标的平均最近距离；
- 按作者原始周期分组的短、中、长期表现；
- 可评价观点数、未成熟数、不可评价原因和覆盖率；
- 每个视频的平均观点得分以及 UP 主的视频等权平均。

为防止一条视频拆出很多观点而放大权重，先在视频内对成熟观点等权平均，再对视频等权平均。`hit=1`、`partial_near=0.5`、`miss=0`；`unresolved`、`superseded` 和 `excluded` 不计分，但必须进入覆盖率分母和原因披露。至少三个含成熟可评价观点的视频才显示排行名次。

## 10. 错误处理与可解释性

- 不把缺行情、周期未知、分时数据缺失或品种不匹配算成失败。
- 不把 API/解析失败保存成“分析完成”或“需要 review”；任务保持可重试。
- 不记录 API 密钥、原始模型响应或完整字幕到日志。
- 所有自动结论必须能从短字幕证据和 OHLC 中间值复算。
- 页面明确区分“作者原话”“M3 时间换算”“程序验证结果”。

## 11. 测试与验收

### 11.1 单元测试

- 多观点 JSON、点位、条件、周期区间和证据定位解析；
- 相对日期与交易日换算，发布当日 K 线排除，周末/休市/时区；
- 目标触达、跌破、站稳、区间、顺序、接近和未成熟规则；
- 无周期观点被下一条同品种预测截断，明确周期观点不被普通日更截断；
- 不同品种不混算，日内观点在只有日线时不可评价；
- 自动有效观点无需人工批准即可统计，人工修订可审计并触发重算；
- 视频等权聚合，避免多观点视频获得额外权重。

### 11.2 集成测试

- 用 fake M3 从一条字幕抽出短、中、长期多观点并完整入库；
- 行情刷新使未成熟观点成熟，而不重复调用模型；
- 新视频使无周期旧观点截止，并支持显式修订关系；
- UP 页面和每个视频详情页展示逐条预测与实际结果；
- 重跑相同字幕、模型和提示词版本保持幂等。

### 11.3 本地真实验收

1. 复用两个指定 UP 主已经保存的 99 条字幕，以 MiniMax-M3、最大并发 3 重新抽取。
2. 不下载媒体，不重新运行 Whisper。
3. 等待全部重分析任务完成或明确失败原因，期间持续处理可恢复错误。
4. 刷新半年 XAU/USD 行情并重算所有成熟观点。
5. 检查两个 UP 页、全部视频详情页、观点覆盖率和排行榜。
6. 抽样核对含“短期/中期/长期”“4700”“突破/跌破/站稳”“回踩后上涨”等表达的视频，确认原话、时间换算和 OHLC 判断一致。
7. 最终运行完整测试、编译、依赖、安全和临时媒体残留检查。

## 12. 明确不做

- 不让 LLM 自行编造或读取未来价格后判断输赢；
- 不用 XAU/USD 代替 COMEX、沪金等其他品种；
- 不用日线数据假装精确验证发布后的日内走势；
- 不模拟真实资金仓位、手续费、滑点或自动交易；
- 不公开部署，不传播完整字幕、音频或视频；
- 不因缺少信息而强制套用 20 天或其他固定默认周期。
