# 日内预测的发布时间后小时级核验设计

日期：2026-08-22

## 目标

Goldbook 必须核验“今天、今晚、日内、未来若干小时、0 个交易日”等短周期预测，且只允许使用视频实际发布时间之后形成的 XAU/USD 行情。系统不能因为只有日线而跳过全部日内预测，也不能使用发布前或横跨发布时间的行情制造事后命中。

## 已确认的根因

当前时间引擎识别出日内词或零交易日期限后，固定返回 `unresolved_intraday_data`。行情层、数据库和评分层只有按日期索引的日线 `PriceBar`，无法表达视频发布时刻、小时 K 线起止时间或小时级首次命中时间。因此修复必须贯穿行情、持久化、时间窗口、评分和 Web 展示，而不是移除一个保护分支。

## 方案选择

采用统一的一小时 XAU/USD 现货 OHLC。XAUS 图表接口的 `symbol=xau&range=1y&interval=1h` 已在本机实测返回 USD 计价的 `Gold (XAU/USD)`、小时级 OHLC 和约一整年数据，覆盖当前两位 UP 的 200 条视频。

不采用“近期五分钟、历史一小时”的混合口径，因为相同预测会因年代不同获得不同核验精度。不在本阶段接入付费分钟或逐笔数据源。

## 行情模型与持久化

新增不可变的 `IntradayPriceBar`：

- `started_at`：带 UTC 时区的小时起点；
- `interval_minutes`：本阶段固定为 60；
- `open/high/low/close`：严格为有限正数，且满足 OHLC 区间约束；
- `provider`：保存实际数据来源名称。

SQLite 新增 `intraday_prices` 表，以 `(started_at, interval_minutes)` 为唯一键。刷新采用事务性 upsert；提供按 UTC 时间范围查询接口。原 `prices` 日线表保持不变，以兼容 1 个及以上交易日的既有评分。

XAUS 小时解析器必须验证 `symbol=xau`、`label=Gold (XAU/USD)`、`currency=USD`、`interval=1h` 和 fresh/upstream 数据状态。不能把黄金期货、其他币种、缓存陈旧数据或非小时数据写入小时表。

`refresh-prices` 同一次刷新日线和小时线；任一来源失败时保留此前缓存并明确报告，不删除已有可核验数据。刷新成功后重算全部最新 claim。

## 严格时间窗口

所有内部时间计算使用 UTC；作者语义截止日期使用 `Asia/Shanghai` 解释，页面也以上海时间展示。

小时 K 线时间戳代表该小时的起点。某根小时线只有在以下条件同时成立时才可用于核验：

1. `bar.started_at >= video.published_at`，因此不会使用发布前或横跨发布时间的价格；
2. `bar.started_at + 60 分钟 <= min(window_end, evaluated_at)`，因此只使用已经完整结束的小时线；
3. 若旧预测被同作者同品种的新预测替代，则不得超过替代时刻。

窗口截止优先级：

1. M3 已提取的明确 `deadline_at`；
2. 明确“未来 N 小时”对应 `published_at + N 小时`；
3. “今天、今日、日内”对应视频发布所在上海自然日的次日 00:00；
4. “今晚、晚间、夜间”对应紧随该视频发布时间之后的上海时间 06:00；若发布时已经超过 06:00，则为次日 06:00；
5. 零交易日但没有更具体词语时，对应视频发布所在上海自然日的次日 00:00。

窗口内尚无一根完整小时线时保持 `unresolved_intraday_data`。窗口尚未结束时，点位类 claim 可在已出现明确命中后提前判为命中；未命中和方向类必须等窗口结束后才成熟，避免把尚未走完的预测提前判错。

## 小时级评分

- 方向预测：第一根合格小时线的开盘价为入场价，最后一根合格小时线的收盘价为截止价；看涨要求截止价高于入场价，看跌要求截止价低于入场价。
- 单点、区间、突破和顺序预测：复用现有确定性 OHLC 判断，但输入改为按时间排序的小时线；最高价、最低价和首次满足顺序均来自发布时间后的合格小时线。
- `HOLD_ABOVE/HOLD_BELOW`：仍要求连续两根完整小时收盘维持在阈值一侧，并在 UI 明示“连续两小时收盘”。
- 条件型预测仍先经过事实核查决定分支是否触发，再进行小时价格判断。

`ClaimEvaluation` 新增可空的 `window_start_at`、`window_end_at`、`closest_at`、`first_hit_at` UTC 时间字段。日线 claim 继续使用原日期字段；小时 claim 使用时间字段，从而保持数据库和现有页面兼容。原因码区分 `unresolved_intraday_data`、`intraday_horizon_not_mature` 和正常的 `hit/miss/partial_near`。

## Web 展示

日内 claim 页面显示：

- 视频发布时间（上海时间）；
- 首根可用小时线时间和入场价；
- 核验截止时间；
- 小时区间最低/最高/最终收盘；
- 首次命中精确到小时；
- 方向比较公式或点位阈值比较说明。

价格图对日内 claim 自动缩放到该小时窗口，展示小时 K 线或小时收盘曲线，并用垂线标记视频发布时间、入场时刻、首次命中和截止时刻。日线 claim 的既有图表保持不变。

## 回填与运行

数据库迁移完成后，先获取覆盖最早视频至当前时刻的一年小时数据，再运行无模型调用的 claim evaluation 重算。M3 已提取的 claim、证据和期限不重新生成；本次只改变行情窗口和确定性核验结果。

回填报告必须列出：识别到的日内 claim 数、成功核验数、尚未成熟数、小时行情缺失数，以及按 UP 分组的命中/接近/未命中分布。

## 错误与安全边界

- 小时接口返回身份、币种、间隔或 fresh 状态不匹配时整批拒绝；
- 网络失败不清空已有小时缓存；
- 不读取浏览器 Cookie，不引入 B 站或交易账户认证；
- API 密钥不进入数据库、页面、日志或测试夹具；
- Web 继续仅绑定 loopback。

## 测试策略

严格按红—绿循环实现：

1. 小时行情解析和错误身份拒绝；
2. 视频在 10:35 发布时，10:00 小时线必须被排除，11:00 才能成为第一根候选；
3. 未完整结束的小时线不得参与判断；
4. 今天、今晚、明确小时数和零交易日的上海时区截止计算；
5. 日内点位命中、方向命中/未命中、顺序和连续两小时 hold；
6. 尚未到截止时间的未命中保持未成熟，但已触及目标允许提前命中；
7. SQLite 迁移、upsert、范围查询和原日线兼容；
8. Web 精确时间与小时图数据；
9. 缓存小时数据上的 200 条视频回填；
10. 全量测试、编译、SQLite 完整性、loopback 页面和敏感信息扫描。

## 完成标准

现有日内 claim 不再因“只有日线”被统一跳过；每个可获得完整小时行情的日内 claim 都严格从视频发布时间之后开始核验，页面能够解释使用了哪些小时价格、为何命中或未命中。所有既有日线评分和事实核查测试保持通过。
